# GAS + AI ブログ記事自動生成(案件2)

Googleスプレッドシートにキーワードを入力すると、Claude AIが記事の下書き(タイトル・本文・メタディスクリプション)を生成し、スプレッドシートに書き出す仕組み。WordPressへの「下書き」投稿コードも実装済みで、設定を切り替えれば実際に投稿することもできる。

## 全体の流れ

```
① スプレッドシートにキーワードを入力
② メニュー「記事生成 → 選択した行で記事を生成」を実行
③ GASがClaude APIを呼び出し、タイトル・本文(HTML)・メタディスクリプションを生成
④ スプレッドシートに書き出す(D列タイトル・E列本文・G列メタディスクリプション)
⑤ WordPressへの送信ペイロードを組み立て、Logger.logに出力(デフォルトでは実際には送信しない)
⑥ ステータス列が 未生成→生成中→生成済み と更新される
```

デフォルトでは `SKIP_REAL_WORDPRESS_POST = true`(Code.gs冒頭)になっており、WordPressへの実投稿はしない。WordPressを用意して実際に下書き投稿まで試したい場合は、この値を `false` にする(その場合はステータスが 投稿中→投稿済み まで進み、F列にWordPressの編集画面リンクが入る)。詳しくは `docs/APIキー設定手順書.md` と `docs/スプレッドシート列構成.md` を参照。

## セットアップ手順

### 1. Googleスプレッドシートを作る

1. [sheets.google.com](https://sheets.google.com) で新しいスプレッドシートを作成
2. メニュー「拡張機能 → Apps Script」を開く
3. エディタに表示されている `コード.gs` の中身を全部削除し、このプロジェクトの `Code.gs` の内容を貼り付けて保存

### 2. シートの雛形を作る

1. スプレッドシートに戻ってページを再読み込みする(リロードするとカスタムメニュー「記事生成」が表示される)
2. メニュー「記事生成 → 設定シートを初期化」を実行
   - 初回は権限の承認を求められるので、Googleアカウントで許可する
   - 「キーワード管理」シートと「設定」シートが自動で作られる

### 3. 「設定」シートに値を入力する

| 項目 | 入力する内容 |
| --- | --- |
| Anthropicモデル | 空欄でOK(デフォルトで `claude-sonnet-5` を使う) |
| WordPress URL | 実際にWordPressへ投稿する場合のみ必要。例: `https://example-saas.com`(末尾のスラッシュは不要) |
| WordPressユーザー名 | 実際にWordPressへ投稿する場合のみ必要 |
| ターゲット読者 | クライアントのヒアリング回答から(例: 中小企業の経営者・情シス担当者) |
| 文字数の目安 | 例: `2000〜3000字` |
| サンプル記事 | クライアントから受け取った「理想の記事」をそのまま貼り付ける(**必須**) |

### 4. APIキーなどを登録する(メニューから)

詳しい手順・スクリーンショットは `docs/APIキー設定手順書.md` を参照。概要は以下の通り。

1. メニュー「記事生成 → 初期設定(APIキーなど)」を実行
2. Anthropic APIキーを入力(console.anthropic.comで発行)
3. WordPressのアプリケーションパスワードを入力(実際にWordPressへ投稿する場合のみ。使わない場合は空欄のままキャンセルでよい)

これらはシートのセルやコードの中ではなく、Script Properties(スクリプトの裏側の設定領域)に保存されるので、スプレッドシートやコードを共有しても他の人には見えない。**APIキーをCode.gsの中に直接書き込まないこと**(コードを共有・公開した瞬間に漏洩するため)。

### 5. 動かしてみる

1. 「キーワード管理」シートのA列にキーワードを1つ入力する(例: 「請求書 電子化」)
2. その行(2行目など)を選択する
3. メニュー「記事生成 → 選択した行で記事を生成」を実行
4. ステータス列が進んでいくのを確認する。「生成済み」になったら、D列(タイトル)・E列(本文)・G列(メタディスクリプション)が埋まっているか確認する

## WordPressへの実投稿を試したい場合

`Code.gs` 冒頭の `SKIP_REAL_WORDPRESS_POST` を `false` に変更し、`docs/InstaWPでテスト環境を作る.md` を参照して無料のWordPressサンドボックスを数分で用意する。

## ファイル構成

```

docs/

  InstaWPでテスト環境を作る.md                # 無料WordPressサンドボックスの用意手順

```

## 設計上の注意点(なぜこうなっているか)

- **status は必ず `'draft'`**: クライアントとの合意(下書き→人間確認→公開)を、コードレベルで強制している。`'publish'` に変更しないこと
- **一度に処理できる行数を制限**: GASは1回の実行が6分までという制限があるため、`MAX_ROWS_PER_RUN`(デフォルト5行)を超える選択はエラーにして、タイムアウトによる中途半端な失敗を防いでいる
- **各段階でステータスとタイムスタンプを書き戻す**: 途中で失敗しても「どこまで進んでいたか」がシートを見るだけで分かるようにしてある
- **APIキー・パスワードはScript Propertiesに保存**: シートのセルやコードに直接書くと、共有時・公開時に漏れるリスクがあるため分離している。詳細は `docs/APIキー設定手順書.md`
- **WordPressへの実投稿はデフォルトで無効**(`SKIP_REAL_WORDPRESS_POST = true`): WordPress連携コード自体は実装済みだが、クライアントのWordPress環境が未整備でも納品できるよう、既定では送信直前のペイロードをログに出すだけに留めている

## 納品物チェックリスト

- [ ] スプレッドシートでキーワード入力 → 記事生成が動作する
- [ ] 記事が指定構成(タイトル + 導入 + H2×3 + まとめ)で生成される
- [ ] 文字数が2,000〜3,000文字の範囲内
- [ ] メタディスクリプションが自動生成される(120字以内)
- [ ] WordPressに下書きとして投稿される、または(未投稿の場合)記事本文+メタディスクリプションがスプレッドシートに書き出されている
- [ ] ステータス管理(生成中→生成済み、実投稿する場合は→投稿済み)が正常に動作する
- [ ] APIキーがScript Propertiesで管理されている(コードに直書きされていない)
- [ ] 3種類のドキュメント(APIキー設定/使い方/トラブルシューティング)が完成している
