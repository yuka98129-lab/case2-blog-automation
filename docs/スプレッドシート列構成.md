# スプレッドシート列構成(「キーワード管理」シート)

| 列 | 項目 | 入力者 | 説明 |
| --- | --- | --- | --- |
| A | キーワード | 人(自分 or クライアント) | 記事のメインキーワード。必須 |
| B | サブキーワード | 人 | SEO関連語。任意 |
| C | ステータス | GASが自動更新 | 未生成/生成中/生成済み/投稿中/投稿済み/エラー |
| D | タイトル | GASが自動入力 | AIが生成した記事タイトル |
| E | 本文 | GASが自動入力 | AIが生成した記事本文(HTML) |
| F | WordPress URL | GASが自動入力 | 実投稿した場合は下書きの編集画面へのリンク。今回は実投稿しない設定(`SKIP_REAL_WORDPRESS_POST = true`)のため、基本は「(未投稿・ログで内容確認のみ)」という文字列が入る |
| G | メタディスクリプション | GASが自動入力 | 検索結果に表示される説明文(120字以内) |
| H | 最終更新日時 | GASが自動入力 | ステータスが更新された日時 |
| I | エラー内容 | GASが自動入力 | エラー発生時のみ、原因を記録 |

教材本文の列構成(A〜E)に、F(メタディスクリプション)・G(更新日時)・H(エラー内容)を追加している。これは「進捗をスプレッドシートに細かく書き戻して途中失敗の影響を最小化する」という設計方針を、実際に目に見える形にするための拡張。

さらに、今回の課題は「実投稿はせず、記事本文+メタディスクリプションをスプレッドシートに書き出すところまで」で完了とする方針(課題resources の「推奨・誰でも完了可」ルート)を採用したため、E列に「本文」を追加している。WordPressへの送信コード自体(`postToWordPressDraft`)は書いてあるが、`Code.gs` 冒頭の `SKIP_REAL_WORDPRESS_POST` が `true` の間は実際には送信されず、送信するはずのペイロード(title / content / status:'draft' / excerpt)が `Logger.log` に出力されるだけになる。実際にWordPressへ投稿するところまで試したい場合は、この値を `false` にし、「設定」シートにWordPress URL・ユーザー名を入力し、「初期設定」メニューでアプリケーションパスワードを登録する。

## 「設定」シート

| セル | 項目 | 備考 |
| --- | --- | --- |
| C2 | Anthropicモデル | 空欄なら `claude-sonnet-5` を使用 |
| C3 | WordPress URL | 例: `https://example-saas.com` |
| C4 | WordPressユーザー名 | |
| C5 | ターゲット読者 | ヒアリング回答から転記 |
| C6 | 文字数の目安 | 例: `2000〜3000字` |
| C7 | サンプル記事 | クライアントの「理想の記事」をそのまま貼り付け |

APIキー・WordPressアプリケーションパスワードはこのシートには書かない(メニューの「初期設定」からScript Propertiesに保存する)。
