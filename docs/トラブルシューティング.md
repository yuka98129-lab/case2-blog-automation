# トラブルシューティング

以下のうち「WordPress投稿エラー」系は、`Code.gs` 冒頭の `SKIP_REAL_WORDPRESS_POST` を `false` にしてWordPressへの実投稿を有効にしている場合のみ発生する。デフォルト設定(`true`)ではWordPressへ通信しないため、これらのエラーは起きない。

## 「Anthropic APIキーが未設定です」

メニュー「記事生成 → 初期設定(APIキーなど)」からAPIキーを登録する。console.anthropic.comで発行したキーが必要。

## 「Claude APIエラー (status 401)」

APIキーが間違っているか、期限切れ・無効化されている。console.anthropic.comでキーを確認し、「初期設定」から入力し直す。

## 「Claude APIエラー (status 429)」

APIの利用上限(レート制限)に達している。少し時間を空けてから再実行する。一度に処理する行数を減らすのも効果的(`MAX_ROWS_PER_RUN` を2〜3に下げる)。

## 「WordPress投稿エラー (status 401)」

WordPressユーザー名またはアプリケーションパスワードが間違っている。

- 「設定」シートのユーザー名が正しいか確認する
- アプリケーションパスワードは「初期設定」メニューから入力し直す(一度発行したパスワードは再表示できないので、分からなくなったらWordPress側で新しく発行し直す)

## 「WordPress投稿エラー (status 403)」

そのユーザーに投稿権限がない可能性がある。WordPress管理画面でユーザーの権限(編集者 以上)を確認する。

## 「WordPress投稿エラー (status 404)」

WordPress URLが間違っているか、REST APIが無効化されている。

- 「設定」シートのWordPress URLを確認する(末尾のスラッシュは不要)
- ブラウザで `(WordPressのURL)/wp-json/wp/v2/posts` を開いて、JSON形式のレスポンスが返ってくるか確認する。エラーページが出る場合はREST APIが無効化されている

## 「WordPress投稿エラー」で status が空、または取得できない

GASからWordPressに到達できていない。以下を確認する。

- WordPressがインターネットに公開されたURLになっているか(`localhost` はGASから接続できない)
- `docs/InstaWPでテスト環境を作る.md` を参照して、公開URLを持つテスト環境を用意する

## 記事生成が毎回同じような内容になる・サンプル記事のトーンが再現できない

- 「設定」シートのサンプル記事が短すぎる、または抽象的すぎる可能性がある。実際の記事を1本まるごと貼り付ける
- プロンプトの制約条件(Code.gs の `buildPrompt` 関数)に、クライアントの好み(文体・語尾・具体例の入れ方など)を追加する

## 処理が途中で止まって終わらない(6分を超えそう)

- 一度に選択する行数を減らす(1行ずつ実行するのが最も安全)
- `MAX_ROWS_PER_RUN` の値をさらに小さくする(Code.gs内で変更可能)

## ステータスが「エラー」のまま進まない

I列(エラー内容)を確認し、上記の該当する対処をしたうえで、同じ行をもう一度選択して「記事生成」を実行する。前の生成結果(タイトルなど)は上書きされるので、やり直しても問題ない。

## 「設定シートが見つかりません」

メニュー「記事生成 → 設定シートを初期化」を一度実行する。すでに自分でシート名を変更してしまった場合は、Code.gs内の `DATA_SHEET_NAME` / `CONFIG_SHEET_NAME` を実際のシート名に合わせて書き換える。
