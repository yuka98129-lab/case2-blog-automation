# 使い方マニュアル

## 日常の使い方(記事を1本生成する)

1. 「キーワード管理」シートを開く
2. 空いている行に、A列へキーワード、B列へサブキーワード(任意)を入力する
3. 入力した行をクリックして選択する(複数行まとめて選んでもよいが、最大5行まで)
4. メニュー「記事生成 → 選択した行で記事を生成」をクリック
5. しばらく待つ(1行あたり数十秒〜1分程度が目安)
6. C列(ステータス)が「生成済み」になったら完了。D列(タイトル)・E列(本文)・G列(メタディスクリプション)を確認する

WordPressへ実際に投稿する設定(`SKIP_REAL_WORDPRESS_POST = false`)にしている場合は、ステータスが「投稿済み」まで進み、F列にWordPress下書きの編集画面リンクが入る。

## ステータスの意味

| ステータス | 意味 |
| --- | --- |
| 未生成 | まだ何も処理していない |
| 生成中 | Claude APIに記事を作らせている最中 |
| 生成済み | 記事(タイトル・本文・メタディスクリプション)が完成し、スプレッドシートに書き出し済み。デフォルト設定ではここが最終状態 |
| 投稿中 | (実投稿を有効にした場合のみ)WordPressへの投稿処理中 |
| 投稿済み | (実投稿を有効にした場合のみ)完了。F列のリンクから下書きを確認できる |
| エラー | 途中で失敗。I列にエラー内容が書かれている |

「生成済み」で止まっているのはデフォルト設定では正常(WordPressへは意図的に投稿していないため)。実投稿を有効にしているのに「生成済み」で止まる場合は、WordPress投稿の直前で何か失敗している可能性が高い。もう一度同じ行を選んで実行すれば、最初からやり直される。

## WordPress送信内容をログで確認する方法

実際にはWordPressへ送信していなくても、「送信するとしたらどんな内容になるか」はログで確認できる。

1. Apps Scriptエディタを開く
2. 左側のアイコンから「実行数」を開く
3. 直近の `generateForSelectedRows` の実行をクリック
4. ログの中に `[WordPress送信ペイロード(確認用・実際には送信していません)]` という文字列とともに、title・content・status:'draft'・excerptを含むJSONが出力されている

## 実データでのテスト(Step3の仕上げ)

クライアントの実際のキーワード5本で試すときは、以下を確認する。

- 記事構成(タイトル/導入/H2×3/まとめ)が指定通りか
- 文字数が設定した範囲に収まっているか
- サンプル記事のトーン・マナーが再現できているか
- メタディスクリプションが120字以内か
- (実投稿する場合)WordPressで「下書き」状態になっていて、誤って公開されていないか

生成した5本のうち1〜2本はクライアントに事前共有してフィードバックをもらうと、納品後の「思ってたのと違う」を防げる。

## 記事の品質が低いと感じたら

`buildPrompt` 関数(Code.gs内)を調整する。特に効果が大きいのは、

1. **サンプル記事を差し替える**: 「設定」シートのサンプル記事を、より理想に近いものに変える
2. **制約条件を具体化する**: 「オリジナルの表現を心がける」だけでなく、「結論を先に書く」「専門用語には簡単な説明を添える」など、クライアントの好みを言語化して追加する
3. **ターゲット読者をより詳しく書く**: 「中小企業の経営者」よりも「従業員50人未満のBtoB企業で、業務効率化のためのツール導入を検討している経営者」のように具体化すると、記事のトーンが安定する
